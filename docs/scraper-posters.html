SortiesPourPetits · scraper/sortiesbot

Le scraper, étage par étage

Comment une recherche web devient une sortie en attente de modération

Python — gratuit Modèle Haiku 4.5 — facturé Site — API et modération

Le partage des rôles

  • 1Le modèle cherche sur le web et classe les pages
  • 2Python télécharge les agendas et en tire les liens
  • 3Le modèle trie les liens, en répondant des numéros
  • 4Python lit la page : texte, JSON-LD, illustration
  • 5Le modèle remplit la fiche, 21 champs imposés
  • 6Python géocode, date, illustre et propose la sortie

Trois appels au modèle, bornés, sans outil et sans boucle. C'est ce découpage qui rend le coût prévisible : environ 0,37 $ pour un run de 20 sorties, contre 2,35 $ pour six sorties avec la version agentique précédente.

1. Découverte

modèle
  • 6 recherches web via l'outil serveur web_search
  • Le modèle classe chaque page : agenda ou sortie
  • Une URL absente des résultats réels est rejetée
  • Mode « site » : les URLs sont données, aucune recherche
  • Plafonds max_searches, max_agendas

Seul étage qui diffère entre les deux modes.

2. Dépouillement des agendas

Python
  • requests + BeautifulSoup, aucun jeton
  • robots.txt lu et respecté, User-Agent identifiable
  • 1 requête par seconde et par hôte, 5 Mo maximum
  • Liens internes seulement (les sortants sont de la pub)
  • 200 caractères de contexte autour de chaque lien
  • Débruitage : mentions légales, pagination, navigation

3. Sélection des liens

modèle
  • Reçoit la liste numérotée des liens et leur contexte
  • Répond des numéros de ligne, jamais des URL
  • Au plus 8 liens retenus par agenda
  • Trie selon le thème, la zone et la période
  • Aucun lien retenu → la page est relue comme une sortie

C'est l'étage qui envoie le plus de texte : jusqu'à 200 liens.

4. Lecture de la page

Python
  • Texte nettoyé, plafonné à 8 000 caractères
  • Dates de représentation lues dans le JSON-LD schema.org
  • Illustration relevée dans og:image / twitter:image
  • Moins de 200 caractères → page écartée sans rien payer
  • Filtres préalables : domaine bloqué, page déjà vue

Le modèle ne voit que le texte : ni le HTML, ni les images.

5. Extraction de la fiche

modèle
  • Schéma JSON de 21 champs imposé par l'API
  • relevant + skip_reason : son droit de veto
  • weekdays / dates : les jours réels, pas la plage
  • Page de programme : jusqu'à 40 fiches d'un seul appel
  • Aucun outil, donc aucune boucle, donc coût prévisible

La page lue ici est celle d'un événement précis, pas un agenda.

6. Publication

Python
  • Géocodage Photon (OpenStreetMap, sans clé)
  • Calendrier résolu en croisant l'annonce et le JSON-LD
  • Photo téléchargée avec la même session HTTP
  • Non géocodé → (0, 0) · tarif inconnu → -1
  • POST /api/events → la sortie arrive en attente de modération

Ce qui tient l'ensemble

Garde-fous

  • URL rejetée si absente des résultats de recherche
  • Sélection par numéros de ligne : aucune URL inventable
  • Schéma JSON imposé côté API
  • Image lue dans le HTML, jamais devinée
  • Aucun appel ne boucle

Budget et plafonds

  • max_cost_usd : arrêt en cours de run
  • max_events, max_page_chars
  • max_agendas, max_links_per_agenda
  • Jetons comptés étage par étage
  • Trois modèles réglables séparément

Mémoire des pages

  • Table ScrapedUrl, commune à toutes les recherches
  • Décision définitive (ne plus relire) ou provisoire
  • Un programme est mémorisé sortie par sortie
  • Oubli possible depuis la console
  • Filtre appliqué avant de payer l'extraction

Ce qu'un run laisse derrière lui

ScraperRun

  • Compteurs : candidats, pages, retenues, soumises
  • Jetons entrée / sortie, recherches web, coût
  • Statut et date, purge possible

ScraperRunItem

  • Une ligne par page traitée
  • url, title, decision, reason
  • at (la date du run) et eventId

ScrapedUrl

  • Mémoire commune à toutes les recherches
  • decision, firstSeen, eventId
  • Empêche de repayer une page connue

Event

  • La sortie proposée, statut PENDING
  • sourceUrl : l'adresse de la page lue
  • Corrigée puis approuvée par un modérateur

Du run au modèle maison

Ce que la base garde déjà, ce qu'il faut reconstruire, et dans quel ordre

Correction — les données d'entraînement existent bel et bien

L'extraction ne lit pas un agenda : elle lit la page d'un événement précis, retenue à l'étage 3 et enregistrée dans Event.sourceUrl. Une fiche de spectacle change bien moins qu'un agenda, qui se réécrit chaque semaine. La question — le texte de la page — est donc récupérable en la re-téléchargeant, et la réponse est déjà en base, relue par un modérateur.

L'objection « la page a changé » vaut pour l'étage sélection, dont les listes de liens ne sont nulle part et dont les agendas se renouvellent : ce corpus-là ne peut être constitué que pour l'avenir. L'extraction, elle, se reconstruit rétroactivement — sous réserve des trois pièges ci-dessous.

A

Ce que la base garde déjà

La question est retrouvable

  • Event.sourceUrl garde l'adresse exacte de la page lue
  • C'est la page d'un événement, pas un agenda
  • Une fiche de spectacle bouge peu : titre, lieu, description
  • Il suffit de la re-télécharger pour retrouver l'entrée

La réponse est déjà propre

  • Event porte la fiche : titre, description, dates, prix, lieu
  • EventDate[] porte les jours réels
  • Et surtout : elle a été relue par un modérateur
  • Un exemple corrigé par un humain vaut mieux qu'un exemple brut

Les refus aussi sont gardés

  • ScraperRunItem.decision = irrelevant, invalid, out_of_period
  • reason donne le motif écrit par le modèle
  • Ce sont les exemples négatifs, indispensables au champ relevant
  • Sans eux, le modèle dirait oui à tout
B

Les trois pièges de la reconstruction

Piège 1 — les pages disparaissent

  • Un site retire souvent ses événements passés (404, redirection)
  • Plus la sortie est ancienne, moins la page répond
  • Se mesure en une après-midi : re-télécharger 200 sourceUrl et compter les 200 OK
  • C'est ce chiffre qui dit si le corpus rétroactif est exploitable

Piège 2 — la page a bougé

  • Dates repoussées, « complet », tarif changé depuis la lecture
  • La paire devient fausse sans prévenir
  • Garde-fou : ne garder que les pages dont le texte contient encore le titre stocké
  • Et privilégier les sorties récentes

Piège 3 — la date du jour

  • Le prompt injecte $today, et une règle en dépend :
  • « jusqu'au 23 octobre » → date_start = la date du run
  • Il faut donc réinjecter ScraperRunItem.at, pas la date d'aujourd'hui
  • Oublier ça rend les étiquettes de dates incohérentes
C

La chaîne, de la base au pipeline

D

Entraîner, puis brancher

Entraîner

  • Partir d'un modèle libre déjà entraîné : Qwen3 1,7 Md, Llama 3.2
  • LoRA : on n'ajuste qu'une petite couche de quelques Mo
  • Quelques heures sur un GPU loué, une dizaine d'euros, une fois
  • Compléter le corpus par distillation si le rétroactif ne suffit pas
  • Ne jamais distiller Haiku : l'élève plafonne sous son professeur

Brancher

  • providers/base.py est un Protocol à trois méthodes
  • Un LocalProvider s'insère sans toucher pipeline.py
  • extractionModel est déjà une colonne de ScraperConfig
  • Deux configurations jumelles = un A/B gratuit
  • Comparer ce que chacune propose à la modération

Dans quel ordre s'y prendre

  1. 1

    Compter ce qui est récupérable

    Combien d'Event avec sourceUrl ? Combien de pages répondent encore ? C'est la seule question qui décide de la suite.

    une après-midi
  2. 2

    Enregistrer les paires dès maintenant

    Écrire le texte envoyé et le JSON reçu à chaque appel. Dix lignes. Le corpus grossit alors tout seul, et la sélection devient entraînable aussi.

    un jour
  3. 3

    Construire le juge

    150 pages mises de côté, la fiche correcte, un script qui compare champ par champ. Faire tourner Haiku dessus : c'est la barre à battre.

    deux jours
  4. 4

    Encaisser les économies gratuites

    JSON-LD étendu, étage sélection dégraissé, API Batch. Même qualité, facture nettement plus basse.

    deux à trois jours
  5. 5

    Reconstruire, entraîner, comparer

    Corpus rétroactif complété par distillation, LoRA sur Qwen3, quantification, LocalProvider. Ne remplacer Haiku que si le juge le permet.

    deux à quatre semaines
